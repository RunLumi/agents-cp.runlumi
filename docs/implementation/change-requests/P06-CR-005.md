# Contract / Plan Change Request — P06-CR-005

## Trigger

Actual desktop adoption creates an active cron automation with `missed_policy:
skip`. In scheduler-resume, the real scheduled handler advances the D1 cursor
past each minute but creates no occurrence. `plan_due_occurrences` applied skip
to every slot in `(cursor, now]`, including an exactly on-time slot. The focused
`skip_missed_policy_keeps_the_current_tick_but_drops_offline_backlog` reproducer
fails on that original implementation.

## Affected phase and packets

- Phase: P06, consumed by DE2E-INT-05.
- Contract Gate: p06-cg-v1; wire shape unchanged.
- Active dependent packets: DE2E-INT-05.
- Merged dependent packets: scheduler behavior requires compatibility review.

## Proposed change

Current: skip discards all enumerated clock slots, so an automation never runs.

New: with the existing minute sweep, the most recent slot less than 60 seconds
old belongs to the current tick. Skip retains at most that slot and discards
older backlog. Exactly 60 seconds old is missed. F15 records the boundary;
canonical slot identity, atomic generation and no replay of started/ambiguous
occurrences remain unchanged. Run-once and bounded catch-up remain unchanged.

## Why this is necessary

The defect is runtime-observed and reproduced at the planner boundary. A sweep
normally runs seconds after its scheduled minute; skip cannot mean disabling
all clock execution. The 0/6/59/60-second controls distinguish current execution
from offline catch-up rather than changing the client's selected policy.

## Compatibility impact

- API/schema/FE types/protocol/migrations: none.
- Security: dispatch still re-evaluates all current authority; no new replay.
- Existing data: existing active skip schedules begin producing current-tick
  work as intended. Old backlog remains skipped. This behavioral change must be
  called out in the release handoff; production deployment remains separate.

## Alternatives considered

1. Change all adopted schedules to run_once: rejected; conceals the broken skip
   behavior and changes the intended backlog policy.
2. Require the sweep to fire at the exact second: rejected; ordinary event-loop
   and platform scheduling delay would still suppress execution.
