# P03-CR-003 — Unbind while retaining run history

Status: accepted for implementation by the integration coordinator; merge awaits runtime gates.

## Trigger

DE2E-INT-04 rendered a real managed Electron response and completed its P05 run.
Rollback after restart still returns 409. Run and P06 automation target binding
references use ON DELETE RESTRICT; closing the session cannot remove historical
references. Evidence: /private/tmp/lumi-electron-account-nrITNi/evidence/result.json
and /private/tmp/lumi-electron-account-persist-10.

## Affected phase and packets

P03-CG v1, P05/P06 consumers, DE2E-INT-03/04 and QA. Coordinator owns binding
queries, both DELETE callers, automation eligibility, migration and contract docs.

## Proposed change

DELETE retains its 204 contract and removes execution authority by marking
removed_at. Ordinary lookup, lists, policy and automation eligibility exclude
removed bindings. A partial unique index permits a fresh explicit bind of the
same device/workspace. Historical runs keep their original binding ID.
No run, usage, approval or audit row is deleted or rewritten.

## Compatibility impact

- API: same active-binding projection and DELETE status; removed rows stay hidden.
- Schema: additive migration 0026; never edit applied migrations.
- Security: every execution lookup and occurrence eligibility rejects removed bindings.
- Existing data: existing rows are active (removed_at IS NULL).
- Rollback: retain this removal-aware backend after migration. Older binaries
  expose tombstones as active; their code-only rollback is incompatible.
  Desktop rollback to local mode remains supported.

## Alternatives considered

Delete run/automation history: violates retention. Null historical run binding
IDs or rebuild their FK: loses durable attribution. Deny rollback after the
first run: contradicts the required local-first journey.

## Merge protocol and proof

Backend gate precedes dependent clients. Update F07, P03 gate, ADR and migration
map. Verify fresh/existing ledgers, retained FK/run history, hidden removed
binding, refused execution using it, and fresh rebind uniqueness. Rerun actual
Electron rollback. Do not claim a migration-safe old-backend rollback.
