# P08-CR-002 — Explicit rebind after rollback

Status: accepted for implementation by goal coordinator; runtime gate pending.

Stage-zero rollback addendum: a local record can already carry reviewed P03
project/device binding metadata. Its rollback clears those IDs and records the
decision even before ladder advancement. A completely unbound local record
still returns AlreadyLocal. UI calls this action "Unbind this workspace."

Actual Electron rollback clears bound_project_id and bound_device_id. A repeat
POST resumes that unbound record unchanged, so the same stable workspace cannot
be adopted again. Evidence: /private/tmp/lumi-electron-account-uIFdWC/evidence/result.json.

Add optional rebind_version to stage-zero adoption POST. Omission preserves
resume behavior. Presence requires an existing local_unmanaged record with local
ownership, no bound IDs and exact version. Project/device must match a live P03
binding with the same opaque workspace identity. Authorize current project
access and active org/device. Commit bound metadata, version increment, immutable
adoption event, security event and outbox in one guarded D1 batch. Stage stays
zero; higher stages still require explicit advancement.

Retain adoption ID, installation/workspace identity, reversion count and events.
No migration/content import. A new P03 binding gets a fresh ID via P03-CR-003.
Active-state rebinding, stale versions, revoked devices, removed/mismatched
bindings and cross-tenant/project requests fail closed.

Coordinator owns migration route/repository, P08 gate, client adoption transport
and workspace owner, tests and INT-03/04 handoff. Backend-first delivery remains
required. Runtime proof: same UI rebind, retained history, new live binding, then
another rollback. Hostile/state and mutation gates remain owed before completion.
