## Outcome
Make the rules that decide whether a local workspace becomes an organization resource readable in one place and testable without a database, an HTTP server, or a clock.

## In scope
- `modules/migration/compatibility.rs`: the frozen protocol and policy-schema ranges, the four-member verdict vocabulary, the degraded-mode guarantee, and the compiled-in baseline that must agree with the seeded row.
- `modules/migration/adoption.rs`: the six F26 stages, ownership, credential mode, the single `apply_stage` transition, `rollback`, external workspace references, the closed-field telemetry parser, the automation-import preview, and remediation derivation.
- `modules/migration/tests.rs`, plus the frozen fixture the tests read.
- `0016_p08_migration_adoption.sql`.

## Explicitly out of scope
- HTTP, D1, and authorization.
- The Lumi Agents client implementation, which is a separate repository.
- Model-capability evaluation, which belongs to P04's route catalog.

## Frozen contracts consumed

## Acceptance criteria
- `apply_stage` is the only function that can move a workspace forward, and only one rank at a time.
- `rollback` is available from every stage and lands on `local_unmanaged` with `local_credential`.
- Every verdict leaves local-only operation available.
- History sync is refused unless the platform enabled it and the credential mode is not local.
- A telemetry report with any key outside the frozen list is refused, not dropped.
- The import preview has no mutating counterpart and never drops a candidate.
- A local-only workspace never produces a remediation.
- `cargo test --workspace` is green.
