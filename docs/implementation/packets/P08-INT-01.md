## Outcome
Ship the client half of the staged adoption path: an optional account, a resumable enrollment wizard, local-versus-managed ownership labels, explicit binding, explicit credential choices, an automation import with conflict preview, offline startup semantics, and a clean unbind.

## In scope (for whoever picks this up)
- The eight-step resumable wizard from P08-CG, driven by `GET /api/v1/compatibility` first and the adoption routes second.
- Ownership labels in the client UI that mirror `Ownership` and `CredentialMode` exactly.
- An import flow that calls `POST .../automation-imports/preview`, shows the returned conflicts, and creates nothing until the user confirms — after which creation goes through P06's ordinary automation route, not a P08 one.
- Offline startup that keeps stage 0 working with no network at all.

## Explicitly out of scope
- Any code path that uploads a local key, a prompt, a file, or an automation body. `p08-cg-v1` gives the client no endpoint that could accept one.
- History sync. The switch is off; a client must not be able to request stage 5.
- Reimplementing anything the control plane owns.

## Why it is not in this pull request
`RunLumi/LumiAgents` is a different repository with its own release cadence and its
own upstream (ZCode) maintenance obligations. Freezing the contract in one place
is what lets the two proceed independently. Attempting to land both in one
change would have coupled a control-plane contract freeze to a client release.

## Acceptance criteria
- The client starts normally with no account and no network.
- An old local session opens.
- Sign-in is optional and never converts a workspace.
- One device and one workspace can be adopted, with the stage ladder matching the server.
- A second workspace stays local, and the client says so rather than prompting.
- Unbind returns the workspace to local-only and the local data is intact.
- No secret or history is uploaded without an explicit choice, and no endpoint exists that would accept one.
