## Two defects the tests caught, recorded because they are the point of the phase

**`hasAdoptionProblem` inferred trouble from `is_managed`.** The first version
returned `true` for any managed workspace, which made the "nothing is wrong with
it" notice dead code and would have nagged every user who adopted anything. The
rule now takes the server's derived codes as a third necessary condition, and
three web tests pin the three cases.

**`stageCountRows` dropped a stage it did not recognize.** A control plane newer
than this build reporting `stage_9` would have had that row's count silently
removed from the distribution, so the visible total would stop matching the table
underneath it. Unknown stages are now appended with their raw value.

Both are the same class of bug: a surface that quietly reports less than it knows.

## Recorded limitations

1. **No browser verification.** The panel is verified with
   `renderToStaticMarkup` against real markup — the load-bearing copy, the

   The P06 handoff records the same gap.
2. **No P08 HTTP smoke.** There is no seeded identity in this repository's

   about authorization. The schema probe covers what `pnpm check` cannot reach, and
   the gap is named rather than filled with a mock.
3. **P08-INT-01 is not in this change.** The Lumi Agents client is a separate
   repository. P08 froze the contract and built the control plane that serves it.

## The three findings worth carrying forward

1. **SQLite does not accept a table-level `CHECK` followed by another column
   definition.** The first version of `0016` placed an ordered-range check beside
   the columns it compared and the migration failed to apply. It was found by
   applying it, not by reading it. All table-level constraints now go last.
2. **Adding a data class without a deletion executor fails a pre-existing P06
   test**, `every_actionable_declared_class_is_either_executable_or_known_gap`.
   That is the test working: a new class that claims to be actionable has to say
   how it is actioned.
3. **"Managed" is not "broken."** The single most likely way for an adoption
   console to go wrong is to treat adoption itself as a problem state.
